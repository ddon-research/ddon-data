= DDON Data
:toc:
:toc-placement!:

Reverse-engineering data for Dragon's Dogma Online (DDON): extracted client resources,
disassembler exports, decrypted network traffic, client patches, and the research tooling built on
top of them.

toc::[]

== About

This repository collects the *output* of several DDON research tools so the results can be
versioned, compared across client builds, and cross-referenced. It covers:

* Client resources of the Season 3 PC client (build `03040008`), extracted to JSON.
* Disassembler exports of the PS4 client (build `02020005`), whose DWARF debug symbols are the main
  source of truth for class layouts, enums, and serialization order.
* Captured, decrypted, and annotated network traffic.
* Binary patches for Windows client executables.
* Research notes, ImHex patterns, and analysis projects (quest flags, knowledge graph, Ghidra/IDA
  automation).

Earlier seasons live in separate repositories:
https://github.com/ddon-research/ddon-data-s1[ddon-data-s1] (Season 1) and
https://github.com/ddon-research/ddon-data-s2[ddon-data-s2] (Season 2, including WIP DWARF-based
recompilation output).

All data is provided for research, interoperability, and educational purposes.

== Data flow

[source]
----
game clients (D:\DDON_<build>\nativePC\rom) ──ddon-extractor──▶ client/<build>/
PS4 DDOORBIS.elf (DWARF) ──IDA / Ghidra──▶ binaries/PS4_<build>/, research/ patterns
PS4 DDOORBIS.elf ──orbis-bin, LLVM (generate-elf-dumps.sh)──▶ binaries/PS4_02020005/elf-dumps/
packet captures (.pcapng) ──split, key bruteforce, Arrowgene CLI──▶ packets/
client/ + binaries/ + reconstructor output ──▶ research/knowledge-graph, research/03040008/flags
----

Downstream tools read this repository: the DDON explorer server (`client/03040008`), the
https://github.com/Sapphiratelaemara/DDON-translation[DDON-translation] tools (quest messages),
the https://github.com/sebastian-heinz/Arrowgene.DragonsDogmaOnline[Arrowgene server emulator]
documentation, and https://github.com/alborrajo/DDOn-Tools[DDOn-Tools] patterns. Keep those paths
stable.

== Toolchain

* Disassembly: IDA Pro 9.5 (with the IDA MCP server and IDA Assist) and Ghidra 11.4 with PyGhidra
  (scripts in link:https://github.com/ddon-research/ddon-ghidra-scripts[ddon-ghidra-scripts], archived).
* Resource extraction: https://github.com/ddon-research/ddon-extractor[ddon-extractor].
* Pattern inspection: ImHex (CLI `imhex --pl format`).
* Packet analysis: Wireshark and `tshark`;
  https://github.com/ddon-research/ddon_common_key_bruteforce[ddon_common_key_bruteforce]
  (fork of https://github.com/Andoryuuta/ddon_common_key_bruteforce[the original]);
  `Arrowgene.Ddon.Cli` from the Arrowgene server emulator.
* Patching: radare2.
* Scripting: bash (Git Bash or WSL), `jq`, `rg`, and `uv`-managed Python 3.14 projects.

== Typical workflows

=== Client resource extraction

. Run ddon-extractor against the client installation, for example
  `ddon-extractor resource -p true -o -m -f json -u -x D:\DDON_03040008 D:\DDON-translation\gmd.csv <out>`.
. Replace `client/<build>/` with the output and regenerate the summary CSV/TXT files.
. Review the change per resource type (`git diff --stat -- client/<build>`) before committing.

=== Resource format research

. Find extensions the extractor does not support yet: `research/scripts/find-unsupported-extensions.sh`.
. Recover the class layout and its `load`/`save` methods from the PS4 debug symbols, through IDA
  or the archived link:https://github.com/ddon-research/ddon-ghidra-scripts[ddon-ghidra-scripts]
  (`headless-scripts/run_ghidra_analysis.sh dwarf|function <name> DDOORBIS.elf`).
. Write an ImHex pattern in `research/03040008/r<Type>-pattern.cpp` and validate it against real
  files with `imhex --pl format --pattern <pattern> --input <file>`.
. Cross-check the result against the extractor JSON. `research/README.adoc` describes the
  LLM-assisted variant of this loop.

=== Packet capture to decrypted streams

`packets/keys/decrypt-pcapng-streams-all-in-one.sh <capture.pcapng|folder> [output_dir]` finds each
stream's session key and decrypts it: link:docs/how-to/decrypt-a-capture.md[Decrypt a capture].
link:docs/how-to/reannotate-streams.md[Re-annotate streams] reprocesses streams whose keys are known,
and `packets/README.md` maps the rest of that directory.
